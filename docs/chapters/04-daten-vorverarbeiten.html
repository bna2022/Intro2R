5.1 Überblick

In dieser Einheit lernen Sie, wie Sie Daten in R so vorbereiten, dass sie analysierbar werden. Im Mittelpunkt stehen drei Pakete aus dem tidyverse:

  • dplyr für das Auswählen, Filtern, Sortieren, Gruppieren und Zusammenfassen von Daten,
  • tidyr für das Umformen von Datensätzen in ein „tidy“ Format,
  • stringr für das Bereinigen von Textwerten.
TipLernziele
  1. Spalten mit select() auswählen oder ausschließen,
  2. Zeilen mit filter() anhand von Bedingungen filtern,
  3. mehrere Arbeitsschritte mit dem Pipe-Operator |> lesbar verknüpfen,
  4. Daten mit arrange() sortieren und mit distinct() Duplikate reduzieren,
  5. Gruppierungen mit group_by() erstellen und mit summarize() zusammenfassen,
  6. Datensätze mit pivot_wider() in ein breiteres, tidy Format bringen,
  7. Zeichenketten mit Funktionen aus stringr bereinigen.

5.2 Tidyverse und Tidy Data

Das Tidyverse kann als moderne Weiterentwicklung der Arbeit mit R verstanden werden. Es wurde wesentlich von Hadley Wickham geprägt. Wickham ist eng mit RStudio verbunden und hat viele zentrale Pakete des Tidyverse mitentwickelt.

Ein wichtiges Grundlagenwerk zum Tidyverse ist das Buch „R for Data Science“ von Wickham und Grolemund. Es wird häufig kurz als R4DS bezeichnet und ist online frei verfügbar:

https://r4ds.hadley.nz/

Das Tidyverse orientiert sich stark am Prinzip der Tidy Data. Dieses Konzept wurde von Wickham beschrieben und legt fest, wie Daten übersichtlich und einheitlich strukturiert werden sollten.

Nach dem Tidy-Data-Prinzip gilt:

  • Jede Beobachtung steht in einer eigenen Zeile.
  • Jede Variable steht in einer eigenen Spalte.
  • Jeder Wert steht in einer eigenen Zelle.

Ein Datensatz ist also dann „tidy“, wenn jede Zeile einen einzelnen Fall beziehungsweise eine einzelne Beobachtung beschreibt. Auch wiederholte Messungen werden jeweils als eigene Zeilen erfasst. Die Merkmale oder Eigenschaften dieser Beobachtungen werden durch die Spalten dargestellt.

5.3 Pakete im Tidyverse

Das Tidyverse ist nicht nur ein einzelnes Paket, sondern eine Sammlung mehrerer R-Pakete, die gut aufeinander abgestimmt sind. Gemeinsam unterstützen sie typische Schritte der Datenanalyse: Daten importieren, bereinigen, umformen, auswerten und visualisieren.

In der Praxis installiert und lädt man häufig das Paket tidyverse. Dadurch werden die wichtigsten Pakete gemeinsam installiert und geladen.

install.packages("tidyverse")
library(tidyverse)

5.4 Datenverarbeitung mit dem Paket dplyr

Bevor wir mit dplyr arbeiten, ist ein Begriff wichtig: Tibble.

Ein Tibble ist eine moderne Variante eines Data Frames. Es bleibt eine tabellarische Datenstruktur: Jede Zeile beschreibt eine Beobachtung, jede Spalte eine Variable. Der Unterschied liegt vor allem in der Darstellung in der Konsole. Tibbles zeigen große Datensätze kompakter an und geben direkt Hinweise auf die Datentypen der Spalten.

Viele Datensätze aus dem Tidyverse, zum Beispiel gapminder, liegen bereits als Tibble vor.

gapminder

Die Ausgabe beginnt zum Beispiel mit:

# A tibble: 1,704 × 6

Das bedeutet: Der Datensatz enthält 1.704 Zeilen und 6 Spalten.

5.5 Warum dplyr?

In den vorherigen Kapiteln haben Sie bereits mit Data Frames gearbeitet. Sie können Spalten mit $ auswählen, Zeilen mit eckigen Klammern filtern und einfache Berechnungen durchführen.

Mit Base R ist also vieles möglich. Bei längeren Analysen wird der Code aber schnell unübersichtlich.

Beispiel:

gapminder[gapminder$country == "Germany" & gapminder$year >= 1990,
          c("country", "year", "lifeExp", "gdpPercap")]

Der Code funktioniert, aber mehrere Dinge stehen gleichzeitig in einem Ausdruck:

  • Welche Zeilen sollen behalten werden?
  • Welche Spalten sollen angezeigt werden?
  • Welche Bedingungen gelten?
  • Was ist eigentlich der nächste Analyseschritt?

Mit dplyr wird dieselbe Idee lesbarer formuliert:

r echo = TRUE gapminder |> filter(country == "Germany", year >= 1990) |> select(country, year, lifeExp, gdpPercap)

Das lässt sich fast wie eine kleine Analyseanweisung lesen:

Nimm den Datensatz gapminder, behalte nur Deutschland ab 1990 und wähle anschließend die interessierenden Spalten aus.

dplyr ersetzt Data Frames also nicht. Es stellt eine übersichtliche Sprache bereit, um besser mit tabellarischen Daten zu arbeiten.

5.6 Grundidee von dplyr

Viele Datenanalysen bestehen aus wiederkehrenden Arbeitsschritten:

  • Zeilen filtern
  • Spalten auswählen
  • Daten sortieren
  • neue Variablen berechnen
  • Gruppen bilden
  • Kennzahlen berechnen

Für diese Arbeitsschritte stellt dplyr gut lesbare Funktionen bereit.

Fragestellung dplyr-Funktion
Welche Zeilen brauche ich? filter()
Welche Spalten brauche ich? select()
Wie sortiere ich die Daten? arrange()
Wie berechne ich neue Variablen? mutate()
Wie fasse ich Daten nach Gruppen zusammen? group_by() und summarise()

Dadurch wird Code leichter verständlich. Das ist nicht nur für Sie selbst hilfreich, sondern auch für andere Personen, die Ihre Analyse später nachvollziehen sollen.

5.7 Beispiel: Arbeitsschritte nacheinander lesen

Mit Base R werden Zeilen- und Spaltenauswahl häufig in einer einzigen Klammer kombiniert:

gapminder[zeilen, spalten]

Das ist mächtig, aber gerade am Anfang auch fehleranfällig. Man muss immer im Blick behalten, was vor und was nach dem Komma steht.

Mit dplyr wird jeder Schritt explizit benannt:

gapminder |>
  filter(continent == "Africa") |>
  select(country, year, lifeExp)

Hier ist klar:

  1. Zuerst werden die Zeilen gefiltert.
  2. Danach werden bestimmte Spalten ausgewählt.

5.8 Weniger Zwischenobjekte

Ohne Pipe und ohne dplyr entstehen bei mehreren Arbeitsschritten oft viele Zwischenobjekte:

africa <- gapminder[gapminder$continent == "Africa", ]
africa_small <- africa[, c("country", "year", "lifeExp")]
africa_2007 <- africa_small[africa_small$year == 2007, ]

Das funktioniert, aber der Workspace wird schnell unübersichtlich.

Mit dplyr und der Pipe können dieselben Schritte kompakt verbunden werden:

gapminder |>
  filter(continent == "Africa") |>
  select(country, year, lifeExp) |>
  filter(year == 2007)

Die Analyse bleibt dadurch näher an der eigentlichen Fragestellung.

5.9 dplyr und Grafiken

Ein weiterer Vorteil ist, dass sich dplyr gut mit anderen Paketen aus dem Tidyverse kombinieren lässt, zum Beispiel mit ggplot2.

gapminder |>
  filter(country == "Germany") |>
  ggplot(aes(x = year, y = lifeExp)) +
  geom_line()

Hier steht die Datenaufbereitung direkt vor der Visualisierung. Dadurch bleibt nachvollziehbar, welche Daten tatsächlich in die Grafik eingehen.

5.10 Merke

dplyr ist keine neue Datenstruktur, sondern eine Sammlung von Funktionen für die Arbeit mit tabellarischen Daten.

Es hilft dabei,

  • Analyseschritte klar zu benennen,
  • Code lesbarer zu schreiben,
  • weniger Zwischenobjekte zu erzeugen,
  • Datenaufbereitung und Visualisierung besser zu verbinden.

Bevor wir die wichtigsten dplyr-Funktionen im Detail kennenlernen, laden wir zunächst die benötigten Pakete und schauen uns den Beispieldatensatz gapminder genauer an.

5.11 Motivation für dplyr

In den vorherigen Übungen haben Sie bereits mit Dataframes gearbeitet. Ein Dataframe ist in R die zentrale Datenstruktur für tabellarische Daten. Sie wissen vermutlich schon, wie man Spalten mit $ anspricht, Zeilen mit eckigen Klammern auswählt und einfache Zusammenfassungen berechnet.

Warum lernen wir jetzt trotzdem noch dplyr?

Weil Dataframes zwar die Datenstruktur sind, aber noch keine besonders gute Sprache für Datenanalyse. Mit base R kann man sehr viel machen, aber bei längeren Analysen wird Code schnell schwer lesbar:

gapminder[gapminder$country == "Germany" & gapminder$year >= 1990,
          c("country", "year", "lifeExp", "gdpPercap")]

Der Code funktioniert, aber er vermischt mehrere Dinge auf einmal:

  • Welche Zeilen sollen behalten werden?
  • Welche Spalten interessieren uns?
  • In welcher Reihenfolge sollen die Schritte passieren?
  • Was ist eigentlich das Ziel dieser Operation?

Mit dplyr schreiben wir dieselbe Idee näher an der natürlichen Sprache:

5.11.1 Warum dplyr, wenn wir schon Dataframes kennen?

5.11.1.1 1. Code wird lesbarer

Viele Analysen bestehen aus mehreren kleinen Schritten: filtern, auswählen, sortieren, neue Variablen berechnen, gruppieren, zusammenfassen. Mit dplyr bekommt jeder dieser Schritte einen klaren Namen.

Fragestellung dplyr-Funktion
Welche Zeilen brauche ich? filter()
Welche Spalten brauche ich? select()
Wie sortiere ich die Daten? arrange()
Wie berechne ich neue Variablen? mutate()
Wie fasse ich Gruppen zusammen? group_by() + summarise()

Dadurch wird der Code nicht nur für Sie selbst verständlicher, sondern auch für andere Personen, die Ihre Analyse nachvollziehen sollen.

5.11.1.2 2. Analysen werden weniger fehleranfällig

Base-R-Code mit eckigen Klammern ist mächtig, aber leicht zu verwechseln:

gapminder[zeilen, spalten]

Wenn Zeilen- und Spaltenlogik in einer einzigen Klammer stehen, passieren schnell Fehler: ein Komma vergessen, eine Spalte falsch geschrieben, eine Bedingung an der falschen Stelle verwendet.

Mit dplyr wird jeder Schritt explizit:

gapminder |>
  filter(continent == "Africa") |>
  select(country, year, lifeExp)

Hier ist klar: Erst werden Zeilen gefiltert, dann Spalten ausgewählt.

5.11.1.3 3. Zwischenschritte werden vermeidbar

Beim Arbeiten mit Dataframes entstehen oft viele Zwischenobjekte:

africa <- gapminder[gapminder$continent == "Africa", ]
africa_small <- africa[, c("country", "year", "lifeExp")]
africa_2007 <- africa_small[africa_small$year == 2007, ]

Das funktioniert, aber der Workspace wird schnell unübersichtlich. Außerdem besteht die Gefahr, später versehentlich mit einem alten Zwischenobjekt weiterzuarbeiten.

Mit einer Pipe-Kette bleibt die Analyse kompakt:

gapminder |>
  filter(continent == "Africa") |>
  select(country, year, lifeExp) |>
  filter(year == 2007)

5.11.1.4 4. Die gleiche Denkweise funktioniert für kleine und große Daten

Bei kleinen Beispieldatensätzen ist base R oft ausreichend. In realen Projekten werden Datensätze aber größer, Analysen länger und Arbeitsschritte wiederholbarer. dplyr bietet eine Grammatik, die mitwächst: vom einfachen Filtern bis zu gruppierten Auswertungen.

5.11.1.5 5. dplyr passt gut zu Grafiken und Berichten

Viele Analysen enden nicht mit einer Tabelle, sondern mit einer Grafik, einem Bericht oder einer statistischen Auswertung. dplyr lässt sich gut mit ggplot2, R Markdown oder Quarto kombinieren:

gapminder |>
  filter(country == "Germany") |>
  ggplot(aes(x = year, y = lifeExp)) +
  geom_line()

Die Datenaufbereitung steht direkt vor der Grafik. Dadurch bleibt nachvollziehbar, welche Daten tatsächlich visualisiert wurden.

5.13.1 Was bedeutet „tibble“?

gapminder ist kein gewöhnlicher Dataframe, sondern ein tibble. Ein tibble ist eine moderne Variante eines Dataframes. Für unsere Arbeit bedeutet das:

  • Ein tibble ist weiterhin tabellarisch aufgebaut: Zeilen sind Beobachtungen, Spalten sind Variablen.
  • Ein tibble kann mit den gleichen Grundideen wie ein Dataframe verwendet werden.
  • Die Ausgabe in der Konsole ist kompakter und übersichtlicher.
  • R zeigt nicht automatisch alle Zeilen und alle Spalten an, sondern nur einen sinnvollen Ausschnitt.

Das ist besonders praktisch, wenn Datensätze größer werden. Bei einem klassischen Dataframe kann die Ausgabe schnell unübersichtlich werden, wenn viele Zeilen oder Spalten vorhanden sind. Ein tibble zeigt stattdessen zuerst eine kurze Zusammenfassung: Anzahl der Zeilen, Anzahl der Spalten, Spaltennamen und Datentypen.

5.13.2 Zeilen, Spalten und Variablen

Die sechs Variablen sind:

Variable Bedeutung Datentyp in R
country Land Faktor / kategoriale Variable
continent Kontinent Faktor / kategoriale Variable
year Jahr Ganzzahl
lifeExp Lebenserwartung bei Geburt numerische Variable
pop Bevölkerungszahl Ganzzahl
gdpPercap Bruttoinlandsprodukt pro Kopf numerische Variable

Die kleinen Angaben unter den Spaltennamen zeigen die Datentypen:

Anzeige Bedeutung
<fct> Faktor, also eine kategoriale Variable
<int> Integer, also eine ganze Zahl
<dbl> Double, also eine numerische Variable mit Dezimalstellen

Diese Informationen sind wichtig, weil viele Funktionen je nach Datentyp unterschiedlich arbeiten. Mit numerischen Variablen können wir zum Beispiel Mittelwerte berechnen. Bei kategorialen Variablen wie continent oder country interessieren uns eher Häufigkeiten oder Gruppenvergleiche.

5.13.3 Ist gapminder wirklich ein Dataframe?

Ein tibble ist eine spezielle Form eines Dataframes. Das können wir mit class() prüfen:

class(gapminder)
[1] "tbl_df"     "tbl"        "data.frame"

Das bedeutet: gapminder ist gleichzeitig ein tibble und ein Dataframe. Die Bezeichnungen tbl_df und tbl zeigen die tibble-Eigenschaften. data.frame zeigt, dass R den Datensatz weiterhin als Dataframe behandeln kann.

Für Sie ist das eine gute Nachricht: Alles, was Sie über Dataframes gelernt haben, bleibt nützlich. dplyr baut darauf auf und bietet eine besser lesbare Sprache für typische Arbeitsschritte.

5.13.4 Ein Dataframe in ein Tibble umwandeln

Mit as_tibble() können wir ein bestehendes Dataframe in ein Tibble umwandeln:

daten_df <- data.frame(
  land = c("Deutschland", "Frankreich", "Italien"),
  jahr = c(2000, 2000, 2000),
  lebenserwartung = c(78.0, 79.1, 79.8)
)

daten_tbl <- as_tibble(daten_df)

daten_tbl
# A tibble: 3 × 3
  land         jahr lebenserwartung
  <chr>       <dbl>           <dbl>
1 Deutschland  2000            78  
2 Frankreich   2000            79.1
3 Italien      2000            79.8

Mit class() können wir prüfen, was daraus geworden ist:

class(daten_tbl)
[1] "tbl_df"     "tbl"        "data.frame"

Die Ausgabe zeigt: Ein Tibble ist weiterhin ein data.frame, hat aber zusätzliche Klassen wie tbl_df und tbl.

Merke:
Ein Dataframe wird mit as_tibble() in ein Tibble umgewandelt.

mein_tibble <- as_tibble(daten_df)

5.13.5 Den Datensatz kompakt untersuchen

Für eine erste Orientierung eignen sich diese Befehle:

nrow(gapminder)      # Anzahl der Zeilen
ncol(gapminder)      # Anzahl der Spalten
names(gapminder)     # Namen der Variablen
class(gapminder)     # Objektklasse

Eine besonders praktische Funktion aus dem tidyverse ist glimpse():

glimpse(gapminder)

glimpse() zeigt jede Variable in einer eigenen Zeile. Das ist hilfreich, weil man schnell erkennt:

  • welche Variablen vorhanden sind,
  • welchen Datentyp sie haben,
  • wie typische Werte aussehen.

Zum Vergleich können Sie auch str() verwenden:

str(gapminder)

Beide Funktionen geben Strukturinformationen aus. glimpse() ist häufig etwas angenehmer zu lesen, besonders bei breiten Tabellen mit vielen Spalten.

5.14 Zeilen auswählen mit filter()

Mit filter() wählen Sie Zeilen aus, die eine Bedingung erfüllen.

5.14.1 Ein Land auswählen

gapminder |>
  filter(country == "Germany")

Dieser Code behält nur Zeilen, in denen country genau den Wert "Germany" hat.

Zum Vergleich in base R:

gapminder[gapminder$country == "Germany", ]

Beide Varianten liefern dasselbe Ergebnis. Die dplyr-Variante ist jedoch näher an der Frage formuliert: „Filtere die Daten auf Deutschland.“

5.14.2 Mehrere Bedingungen verwenden

gapminder |>
  filter(country == "Germany", year >= 1990)

Mehrere Bedingungen innerhalb von filter() werden wie ein logisches UND behandelt. Es bleiben also nur Zeilen erhalten, bei denen alle Bedingungen erfüllt sind.

Sie können Bedingungen auch explizit mit & verbinden:

gapminder |>
  filter(country == "Germany" & year >= 1990)

5.14.3 Mehrere Länder auswählen

Für mehrere mögliche Werte nutzen Sie %in%:

gapminder |>
  filter(country %in% c("Germany", "France", "Italy"))

Das liest sich als: Behalte Zeilen, bei denen country in der angegebenen Liste vorkommt.

5.16 Arbeitsschritte verbinden mit |>

Der Pipe-Operator |> übergibt das Ergebnis eines Schrittes an den nächsten Schritt. Man kann ihn als „dann“ lesen.

5.18 Neue Variablen berechnen mit mutate()

Mit mutate() erzeugen Sie neue Spalten oder verändern bestehende Spalten.

5.18.1 Bevölkerung in Millionen

Die Spalte pop enthält absolute Bevölkerungszahlen. Für Tabellen ist eine Angabe in Millionen oft lesbarer.

gapminder |>
  mutate(pop_mio = pop / 1000000) |>
  select(country, year, pop, pop_mio)

5.18.2 BIP insgesamt schätzen

gdpPercap ist das BIP pro Kopf. Eine grobe Schätzung des gesamten BIP erhalten Sie durch Multiplikation mit der Bevölkerung:

gapminder |>
  mutate(gdp_total = gdpPercap * pop) |>
  select(country, year, pop, gdpPercap, gdp_total)

5.18.3 Lebenserwartung kategorisieren

gapminder |>
  mutate(lifeExp_group = case_when(
    lifeExp < 50 ~ "unter 50",
    lifeExp < 70 ~ "50 bis unter 70",
    TRUE ~ "70 und mehr"
  )) |>
  select(country, year, lifeExp, lifeExp_group)

case_when() ist nützlich, wenn Sie mehrere Bedingungen in Kategorien übersetzen möchten. Die letzte Zeile TRUE ~ "70 und mehr" aus dem Beispiel funktioniert hier wie eine Auffangkategorie: Alle Beobachtungen, die keine der vorherigen Bedingungen erfüllen, erhalten diesen Wert.

5.20 Gruppieren und zusammenfassen mit group_by() und summarise()

Viele Forschungsfragen beziehen sich nicht auf einzelne Zeilen, sondern auf Gruppen:

  • Wie hoch ist die durchschnittliche Lebenserwartung pro Kontinent?
  • Wie verändert sich die Bevölkerung pro Kontinent über die Zeit?
  • Welche Länder haben die höchste oder niedrigste Lebenserwartung?

Dafür kombinieren wir group_by() und summarise().

5.20.1 Durchschnittliche Lebenserwartung pro Kontinent

gapminder |>
  filter(year == 2007) |>
  group_by(continent) |>
  summarise(mean_lifeExp = mean(lifeExp))

Dieser Code bedeutet:

  1. Behalte nur das Jahr 2007.
  2. Gruppiere die Daten nach Kontinent.
  3. Berechne pro Kontinent die mittlere Lebenserwartung.

5.20.2 Mehrere Kennzahlen berechnen

gapminder |>
  filter(year == 2007) |>
  group_by(continent) |>
  summarise(
    mean_lifeExp = mean(lifeExp),
    min_lifeExp = min(lifeExp),
    max_lifeExp = max(lifeExp),
    n_countries = n()
  )

n() zählt, wie viele Zeilen in jeder Gruppe enthalten sind.

5.20.3 Gruppierung über mehrere Variablen

gapminder |>
  group_by(continent, year) |>
  summarise(mean_lifeExp = mean(lifeExp), .groups = "drop")

Jetzt wird für jede Kombination aus Kontinent und Jahr eine Zusammenfassung berechnet. Das Argument .groups = "drop" sorgt dafür, dass die Gruppierung nach der Zusammenfassung wieder aufgehoben wird. Das Ergebnis ist dadurch eine normale Tabelle und spätere Berechnungen werden nicht versehentlich weiterhin gruppiert ausgeführt.

5.21 Daten umformen mit tidyr

Bisher haben wir mit dplyr Daten gefiltert, sortiert, umbenannt, gruppiert und zusammengefasst. Das funktioniert besonders gut, wenn die Daten bereits in einer geeigneten Form vorliegen.

In der Praxis liegen Daten aber häufig nicht genau so vor, wie wir sie für eine Analyse brauchen. Manchmal stehen mehrere Messzeitpunkte in verschiedenen Spalten. Manchmal stehen Variablennamen als Werte in einer Spalte. Für solche Fälle nutzen wir tidyr.

tidyr hilft dabei, Daten in eine tidy Form zu bringen.

5.21.1 Was bedeutet tidy data?

Eine Tabelle ist tidy, wenn sie drei Grundregeln erfüllt:

  1. Jede Variable steht in einer eigenen Spalte.
  2. Jede Beobachtung steht in einer eigenen Zeile.
  3. Jeder Wert steht in einer eigenen Zelle.

Diese Regeln klingen zunächst einfach. Sie sind aber sehr hilfreich, weil viele Funktionen aus dem tidyverse genau mit dieser Struktur besonders gut arbeiten.

5.22 Textdaten bereinigen mit stringr

Bisher haben wir Daten mit dplyr bearbeitet und mit tidyr umgeformt. Manchmal liegt das Problem aber nicht in der Tabellenstruktur, sondern in den Textwerten selbst.

Typische Probleme bei Textdaten sind:

  • zusätzliche Leerzeichen,
  • unterschiedliche Groß- und Kleinschreibung,
  • uneinheitliche Schreibweisen,
  • Werte, die nur teilweise gesucht oder ersetzt werden sollen.

Für solche Aufgaben nutzen wir das Paket stringr.

5.22.1 Ein kleines Beispiel mit Ländernamen

Der gapminder-Datensatz ist bereits sehr sauber. Damit wir typische Probleme sehen können, erzeugen wir zunächst eine kleine fehlerhafte Version einiger Ländernamen.

library(tidyverse)
library(gapminder)

laender_roh <- tibble(
  country = c(" Germany", "france", "ITALY ", "United  Kingdom", "bosnia and herzegovina"),
  year = c(2007, 2007, 2007, 2007, 2007),
  lifeExp = c(79.4, 80.7, 80.5, 79.4, 74.9)
)

laender_roh
# A tibble: 5 × 3
  country                   year lifeExp
  <chr>                    <dbl>   <dbl>
1 " Germany"                2007    79.4
2 "france"                  2007    80.7
3 "ITALY "                  2007    80.5
4 "United  Kingdom"         2007    79.4
5 "bosnia and herzegovina"  2007    74.9

Die Ländernamen sind hier absichtlich uneinheitlich geschrieben.

5.22.2 Leerzeichen bereinigen

Mit str_trim() entfernen wir Leerzeichen am Anfang und Ende eines Textes. Mit str_squish() entfernen wir zusätzlich überflüssige Leerzeichen innerhalb eines Textes.

laender_roh |>
  mutate(
    country_clean = country |>
      str_trim() |>
      str_squish()
  )
# A tibble: 5 × 4
  country                   year lifeExp country_clean         
  <chr>                    <dbl>   <dbl> <chr>                 
1 " Germany"                2007    79.4 Germany               
2 "france"                  2007    80.7 france                
3 "ITALY "                  2007    80.5 ITALY                 
4 "United  Kingdom"         2007    79.4 United Kingdom        
5 "bosnia and herzegovina"  2007    74.9 bosnia and herzegovina

Der Unterschied ist wichtig:

  • str_trim() entfernt Leerzeichen außen.
  • str_squish() reduziert mehrere Leerzeichen innerhalb eines Textes auf ein einzelnes Leerzeichen.

5.22.3 Groß- und Kleinschreibung vereinheitlichen

Mit str_to_title() können wir Text in eine einheitliche Schreibweise bringen.

laender_clean <- laender_roh |>
  mutate(
    country_clean = country |>
      str_trim() |>
      str_squish() |>
      str_to_title()
  )

laender_clean
# A tibble: 5 × 4
  country                   year lifeExp country_clean         
  <chr>                    <dbl>   <dbl> <chr>                 
1 " Germany"                2007    79.4 Germany               
2 "france"                  2007    80.7 France                
3 "ITALY "                  2007    80.5 Italy                 
4 "United  Kingdom"         2007    79.4 United Kingdom        
5 "bosnia and herzegovina"  2007    74.9 Bosnia And Herzegovina

Jetzt sind die Ländernamen deutlich einheitlicher.

5.22.4 Textmuster suchen mit str_detect()

Mit str_detect() können wir prüfen, ob ein Text ein bestimmtes Muster enthält.

laender_clean |>
  mutate(
    contains_united = str_detect(country_clean, "United")
  )
# A tibble: 5 × 5
  country                   year lifeExp country_clean          contains_united
  <chr>                    <dbl>   <dbl> <chr>                  <lgl>          
1 " Germany"                2007    79.4 Germany                FALSE          
2 "france"                  2007    80.7 France                 FALSE          
3 "ITALY "                  2007    80.5 Italy                  FALSE          
4 "United  Kingdom"         2007    79.4 United Kingdom         TRUE           
5 "bosnia and herzegovina"  2007    74.9 Bosnia And Herzegovina FALSE

Das Ergebnis ist eine neue logische Spalte mit TRUE oder FALSE.

Das können wir auch direkt zum Filtern nutzen:

laender_clean |>
  filter(str_detect(country_clean, "United"))
# A tibble: 1 × 4
  country          year lifeExp country_clean 
  <chr>           <dbl>   <dbl> <chr>         
1 United  Kingdom  2007    79.4 United Kingdom

5.22.5 Schreibweisen gezielt korrigieren

Manchmal reicht eine automatische Bereinigung nicht aus. Zum Beispiel ist "Bosnia And Herzegovina" zwar formal vereinheitlicht, aber nicht die übliche Schreibweise im gapminder-Datensatz.

laender_clean <- laender_clean |>
  mutate(
    country_clean = case_when(
      str_detect(country_clean, "Bosnia") ~ "Bosnia and Herzegovina",
      TRUE ~ country_clean
    )
  )

laender_clean
# A tibble: 5 × 4
  country                   year lifeExp country_clean         
  <chr>                    <dbl>   <dbl> <chr>                 
1 " Germany"                2007    79.4 Germany               
2 "france"                  2007    80.7 France                
3 "ITALY "                  2007    80.5 Italy                 
4 "United  Kingdom"         2007    79.4 United Kingdom        
5 "bosnia and herzegovina"  2007    74.9 Bosnia and Herzegovina

Die letzte Zeile TRUE ~ country_clean bedeutet: Wenn keine der vorherigen Bedingungen zutrifft, bleibt der ursprüngliche bereinigte Wert erhalten.

5.22.6 Warum ist das wichtig?

Saubere Textwerte sind wichtig, weil R Zeichenketten exakt vergleicht. Für R sind diese Werte unterschiedlich:

"Germany" == " Germany"
[1] FALSE
"Germany" == "germany"
[1] FALSE
"United Kingdom" == "United  Kingdom"
[1] FALSE

Solche Unterschiede können dazu führen, dass Filter, Gruppierungen oder Joins nicht wie erwartet funktionieren.

5.22.7 Beispiel: Gruppieren nach bereinigten Ländernamen

laender_roh |>
  mutate(
    country_clean = country |>
      str_trim() |>
      str_squish() |>
      str_to_title()
  ) |>
  group_by(country_clean) |>
  summarise(
    mean_lifeExp = mean(lifeExp),
    .groups = "drop"
  )
# A tibble: 5 × 2
  country_clean          mean_lifeExp
  <chr>                         <dbl>
1 Bosnia And Herzegovina         74.9
2 France                         80.7
3 Germany                        79.4
4 Italy                          80.5
5 United Kingdom                 79.4

Hier sorgt die Bereinigung dafür, dass gleiche Länder nicht versehentlich als verschiedene Gruppen behandelt werden.

5.22.8 Übung

Erstellen Sie eine kleine Tabelle mit uneinheitlichen Kontinentnamen:

kontinente_roh <- tibble(
  continent = c(" europe", "Europe ", "EUROPE", "asia", "Asia  "),
  value = c(1, 2, 3, 4, 5)
)

Bereinigen Sie die Spalte continent so, dass daraus einheitliche Werte entstehen.

Nutzen Sie dafür:

  • str_trim()
  • str_squish()
  • str_to_title()

5.22.9 Merke

stringr hilft uns, Textwerte zu bereinigen und zu durchsuchen.

Wichtige Funktionen sind:

str_trim(text)       # Leerzeichen am Anfang und Ende entfernen
str_squish(text)     # Mehrfache Leerzeichen reduzieren
str_to_title(text)   # Einheitliche Groß-/Kleinschreibung
str_detect(text, "Muster")  # Textmuster erkennen

5.23 Zusammenfassung

In dieser Einheit haben Sie gelernt:

  • Mit select() wählen Sie Spalten aus oder schließen sie aus.
  • Mit filter() behalten Sie nur Zeilen, die eine Bedingung erfüllen.
  • Mit dem Pipe-Operator |> schreiben Sie Datenanalyse-Code schrittweise und lesbar.
  • Mit arrange() sortieren Sie Daten.
  • Mit distinct() reduzieren Sie wiederholte Beobachtungen.
  • Mit group_by() und summarize() berechnen Sie gruppierte Kennzahlen.
  • Mit pivot_wider() formen Sie lange Daten in breite Daten um.
  • Mit stringr bereinigen Sie Textwerte.
