6.1 Lernziele

Nach diesem Kapitel können Sie:

  • den Unterschied zwischen explorativer und erklärender Datenvisualisierung beschreiben,
  • einfache Grafiken mit ggplot2 erstellen,
  • die Grundidee der Grammar of Graphics erklären,
  • Variablen auf visuelle Eigenschaften wie Position, Farbe, Form oder Größe abbilden,
  • geeignete Diagrammtypen für eindimensionale und zweidimensionale Daten auswählen,
  • Facetten, Farben, Achsenskalierungen und Themes gezielt einsetzen,
  • Grafiken reproduzierbar speichern.

6.2 Warum Daten visualisieren?

Datenvisualisierung hat in der Statistik und Datenanalyse zwei zentrale Aufgaben.

Erstens hilft sie bei der Exploration. Bevor formale Modelle oder Tests eingesetzt werden, können Grafiken zeigen, welche Muster, Ausreißer, Gruppenunterschiede oder Zusammenhänge in den Daten vorhanden sind.

Zweitens dient Visualisierung der Kommunikation. Eine gute Grafik fasst eine Aussage so zusammen, dass andere sie schnell verstehen können. Dabei geht es nicht nur darum, eine „schöne“ Grafik zu erzeugen, sondern darum, eine inhaltliche Aussage klar und ehrlich zu vermitteln.

Beispielhafte Fragen, die man mit Visualisierungen untersuchen kann:

  • Wie ist eine Variable verteilt?
  • Gibt es Ausreißer?
  • Hängen zwei Variablen zusammen?
  • Unterscheiden sich Gruppen voneinander?
  • Gibt es nichtlineare Zusammenhänge?
  • Gibt es Muster, die in einer Tabelle schwer erkennbar wären?

6.4 Weitere Grafiken mit Base R

Base R enthält bereits viele Funktionen, um Daten schnell explorativ zu visualisieren. Im Folgenden werden einige Beispiele mit dem Datensatz Pima.tr gezeigt.

6.4.1 Histogramm

Ein Histogramm zeigt die Verteilung einer metrischen Variable. Hier wird untersucht, wie die Glukosewerte verteilt sind.

hist(Pima.tr$glu,
     breaks = 20,
     main = "Verteilung der Glukosewerte",
     xlab = "Glukosewert",
     ylab = "Häufigkeit")

6.4.2 Boxplot

Ein Boxplot zeigt Median, Quartile und mögliche Ausreißer. Hier werden die Glukosewerte getrennt nach Diabetes-Status dargestellt.

boxplot(glu ~ type,
        data = Pima.tr,
        main = "Glukosewerte nach Diabetes-Status",
        xlab = "Diabetes-Status",
        ylab = "Glukosewert")

6.4.3 Streudiagramm

Ein Streudiagramm eignet sich, um den Zusammenhang zwischen zwei metrischen Variablen zu betrachten.

plot(Pima.tr$bmi, Pima.tr$glu,
     main = "Zusammenhang zwischen BMI und Glukosewert",
     xlab = "BMI",
     ylab = "Glukosewert",
     pch = 19)

6.4.4 Streudiagramm mit Gruppenfarben

Die Punkte können nach Diabetes-Status eingefärbt werden. Dadurch sieht man, ob sich Gruppen im Diagramm unterschiedlich verteilen.

plot(Pima.tr$bmi, Pima.tr$glu,
     main = "BMI und Glukosewert nach Diabetes-Status",
     xlab = "BMI",
     ylab = "Glukosewert",
     pch = 19,
     col = ifelse(Pima.tr$type == "Yes", "red", "blue"))

legend("topleft",
       legend = c("Diabetes: Yes", "Diabetes: No"),
       col = c("red", "blue"),
       pch = 19)

6.4.5 Dichteplot

Ein Dichteplot ist eine geglättete Alternative zum Histogramm. Er zeigt ebenfalls die Verteilung einer metrischen Variable.

plot(density(Pima.tr$glu),
     main = "Dichte der Glukosewerte",
     xlab = "Glukosewert")

6.4.6 Mehrere Histogramme nebeneinander

Mit par(mfrow = c(...)) können mehrere Grafiken in einem gemeinsamen Grafikbereich dargestellt werden.

par(mfrow = c(1, 2))

hist(Pima.tr$glu,
     breaks = 20,
     main = "Glukose",
     xlab = "Glukosewert")

hist(Pima.tr$bmi,
     breaks = 20,
     main = "BMI",
     xlab = "BMI")
par(mfrow = c(1, 1))

6.4.7 Scatterplot-Matrix

Eine Scatterplot-Matrix zeigt paarweise Streudiagramme mehrerer metrischer Variablen. Dadurch lassen sich mögliche Zusammenhänge schnell erkennen.

pairs(Pima.tr[, c("npreg", "glu", "bp", "bmi", "age")],
      main = "Scatterplot-Matrix ausgewählter Variablen")

Eine Heatmap stellt Werte farblich dar. Hier wird sie verwendet, um die Korrelationsmatrix zu visualisieren. Stärkere Zusammenhänge werden dadurch schneller sichtbar.

6.4.10 Einfachere Heatmap ohne Umordnung (Optional)

Standardmäßig ordnet heatmap() die Zeilen und Spalten nach Ähnlichkeit um. Für den Einstieg kann es verständlicher sein, diese Umordnung auszuschalten.

heatmap(korrelationen,
        main = "Heatmap der Korrelationen ohne Umordnung",
        symm = TRUE,
        Rowv = NA,
        Colv = NA)

6.5 Von Base R zu ggplot2

ggplot2 verfolgt einen anderen Ansatz. Man beschreibt nicht Schritt für Schritt, wo etwas gezeichnet wird, sondern formuliert, welche Variablen wie dargestellt werden sollen.

Zuerst laden wir das Paket:

library(ggplot2)
Warning: Paket 'ggplot2' wurde unter R Version 4.4.3 erstellt

Der einfache Scatterplot aus Base R sieht in ggplot2 so aus:

ggplot(Pima.tr, aes(x = age, y = glu)) +
  geom_point()

Dieser Code bedeutet:

  • Verwende den Datensatz Pima.tr.
  • Trage age auf der x-Achse ab.
  • Trage glu auf der y-Achse ab.
  • Stelle die Beobachtungen als Punkte dar.

6.6 Die Grundidee von ggplot2

Das Paket ggplot2 basiert auf der Idee der Grammar of Graphics von Leland Wilkinson. Die zentrale Frage dahinter lautet nicht: „Welchen Diagrammtyp möchte ich zeichnen?“, sondern:

Aus welchen Bausteinen besteht eine Grafik?

Vor der Grammar-of-Graphics-Idee wurden Grafiken häufig als feste Diagrammtypen verstanden, zum Beispiel als Balkendiagramm, Liniendiagramm, Streudiagramm oder Boxplot. Wilkinson schlug dagegen vor, Grafiken wie eine Sprache zu betrachten. So wie ein Satz aus Wörtern und grammatischen Regeln aufgebaut ist, kann auch eine Grafik aus einzelnen Komponenten zusammengesetzt werden. Wenn uns diese Elemente bekannt sind, können wir Grafiken besser verstehen und verändern.

Die Grammar of Graphics unterscheidet die folgenden Komponenten:

Komponente Bedeutung
Daten Der Datensatz, der visualisiert werden soll
Ästhetiken Zuordnung von Datenvariablen zu visuellen Eigenschaften, z. B. Achsenposition, Farbe, Form
Geometrien Die Art der Darstellung, z. B. Punkte, Linien, Balken
Statistiken Berechnungen auf den Daten, z. B. Zählen, Glätten oder Binning
Skalen Umsetzung von Datenwerten in Achsen, Farben oder Größen
Koordinaten Koordinatensystem, meistens kartesisch
Facetten Aufteilung in mehrere Teilgrafiken
Theme Gestaltung, z. B. Schriftgrößen, Hintergrund, Legende

ggplot2 überträgt diese Idee auf R. Das Paket wurde von Hadley Wickham entwickelt und macht die Grammar of Graphics praktisch nutzbar. Eine Grafik wird dabei schrittweise aufgebaut. Man beginnt mit den Daten, legt dann fest, welche Variablen auf welche ästhetischen Eigenschaften abgebildet werden, und ergänzt anschließend die gewünschte Darstellungsform.

Ein einfacher ggplot besteht meistens aus drei Teilen:

ggplot(data = DATENSATZ, aes(x = VARIABLE1, y = VARIABLE2)) +
  geom_...()

Beispiel:

ggplot(data = Pima.tr, aes(x = age, y = glu)) +
  geom_point()

6.7 Ästhetiken: Variablen sichtbar machen

Die Funktion aes() beschreibt, welche Variable auf welche visuelle Eigenschaft abgebildet wird.

ggplot(Pima.tr, aes(x = age, y = glu)) +
  geom_point()

Hier werden zwei Variablen verwendet:

  • age: Position auf der x-Achse
  • glu: Position auf der y-Achse

Zusätzlich kann eine dritte Variable über Farbe dargestellt werden:

ggplot(Pima.tr, aes(x = age, y = glu, color = type)) +
  geom_point(size = 3)

Hier zeigt die Farbe den Diabetesstatus (type).

Typische Ästhetiken sind:

Ästhetik Bedeutung
x Position auf der x-Achse
y Position auf der y-Achse
color Farbe von Linien oder Punkten
fill Füllfarbe, z. B. bei Balken oder Boxplots
shape Symbolform
size Größe
alpha Transparenz
linetype Linientyp

Wichtig ist die Unterscheidung zwischen Eigenschaften innerhalb und außerhalb von aes().

Wenn eine Eigenschaft von einer Variable abhängen soll, steht sie innerhalb von aes():

ggplot(Pima.tr, aes(x = age, y = glu, color = type)) +
  geom_point()

Wenn eine Eigenschaft für alle Punkte gleich sein soll, steht sie außerhalb von aes():

ggplot(Pima.tr, aes(x = age, y = glu)) +
  geom_point(color = "blue")

6.8 Geometrien: Wie sollen die Daten dargestellt werden?

Die Geometrie legt fest, welche grafischen Objekte verwendet werden. In ggplot2 werden diese grafischen Objekte mit Funktionen beschrieben, die mit geom_ beginnen. Beispiele sind geom_point() für Punkte, geom_line() für Linien, geom_histogram() für Histogramme oder geom_boxplot() für Boxplots.

Als Beispieldatensatz verwenden wir im Folgenden den Datensatz DNase, der in R bereits enthalten ist. Der Datensatz speichert Messwerte aus einem biologischen Experiment zur Aktivität des Enzyms DNase. Dabei wurde untersucht, wie sich unterschiedliche Konzentrationen eines Stoffes auf die optische Dichte auswirken.

Der Datensatz enthält drei zentrale Variablen:

  • Run: Kennzeichnung des Versuchslaufs
  • conc: Konzentration
  • density: gemessene optische Dichte

Jede Zeile beschreibt eine Messung: Bei einer bestimmten Konzentration wurde in einem bestimmten Versuchslauf die optische Dichte gemessen.

data(DNase)

head(DNase)
  Run       conc density
1   1 0.04882812   0.017
2   1 0.04882812   0.018
3   1 0.19531250   0.121
4   1 0.19531250   0.124
5   1 0.39062500   0.206
6   1 0.39062500   0.215

6.8.1 Punktdiagramm (Scatterplots)

Punktdiagramme (Scatterplots, Streudiagramme) eignen sich gut, um den Zusammenhang zwischen zwei metrischen Variablen zu untersuchen.

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point()

Interpretation: Mit steigender Konzentration steigt tendenziell auch die optische Dichte. Der Zusammenhang ist aber nicht einfach linear, sondern flacht bei höheren Konzentrationen ab.

Eine etwas bessere lesbare Variante verwendet eine logarithmische Skalierung der x-Achse, weil die Konzentrationen nicht gleichmäßig verteilt sind.

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  scale_x_log10()

6.8.2 Liniendiagramm

Da die Messungen innerhalb eines Versuchslaufs bei verschiedenen Konzentrationen durchgeführt wurden, kann man die Punkte pro Run auch verbinden.

ggplot(DNase, aes(x = conc, y = density, group = Run)) +
  geom_line() +
  geom_point()

Hier ist group = Run wichtig: Dadurch weiß ggplot2, welche Punkte miteinander verbunden werden sollen.

6.8.3 Histogramm

Ein Histogramm zeigt die Verteilung einer metrischen Variable.

ggplot(DNase, aes(x = density)) +
  geom_histogram(bins = 25)

Die Wahl der Klassenanzahl oder Klassenbreite beeinflusst die Darstellung. Eine zu feine Einteilung erzeugt ein unruhiges Bild, eine zu grobe Einteilung kann wichtige Muster verdecken.

ggplot(DNase, aes(x = density)) +
  geom_histogram(binwidth = 0.1)

6.8.4 Dichteplot

Ein Dichteplot ist eine geglättete Darstellung einer Verteilung.

ggplot(DNase, aes(x = density)) +
  geom_density()

Dichteplots eignen sich gut, wenn man mehrere Verteilungen vergleichen möchte.

ggplot(DNase, aes(x = density, color = Run)) +
  geom_density()

Das Argument bw der Funktion geom_density() erlaubt es, die Bandbreite eines Dichteplots manuell anzupassen. Standardmäßig wird eine automatische Regel zur Wahl der Bandbreite verwendet, was meistens eine gute Wahl ist. Die folgende Visualisierung zeigt einen Dichteplot mit einer kleiner gewählten Bandbreite.

ggplot(DNase, aes(x = density, color = Run)) +
  geom_density(bw=0.06)

6.8.5 Boxplot

Boxplots eignen sich, um Verteilungen zwischen Gruppen zu vergleichen. Sie zeigen den Median, die Quartile, und Extremwerte einer Verteilung. Eine gute Illustrierung und Erklärung gibt es hier https://web.pdx.edu/~stipakb/download/PA551/boxplot.html.

Jeder Boxplot hat Linien bei Q1, beim Median und bei Q3. Zusammen bilden diese Werte die Box des Boxplots. Ein weiteres wichtiges Merkmal eines Boxplots sind die Whisker. Diese werden mithilfe des Interquartilsabstands berechnet:

\[IQR = Q3 - Q1\]

Datenpunkte, die außerhalb des Bereichs \(Q1 - 1{,}5 \times IQR\) bis \(Q3 + 1{,}5 \times IQR\) liegen, werden als Ausreißer bezeichnet.

ggplot(DNase, aes(x = factor(Run, levels = 1:11), y = density)) +
  geom_boxplot() +
  labs(
    x = "Versuchslauf",
    y = "Dichte",
    title = "Dichtewerte nach Versuchslauf"
  )

Dabei wird für jeden Versuchslauf die Verteilung der optischen Dichte zusammengefasst. Damit die Versuchsläufe in der richtigen Reihenfolge angezeigt werden, kann Run in einen Faktor mit festgelegter Reihenfolge umgewandelt werden:

ggplot(DNase, aes(x = factor(Run, levels = 1:11), y = density)) +
  geom_boxplot()

ggplot2 behandelt Run hier als kategoriale Variable. Mit levels = 1:11 wird festgelegt, dass die Versuchsläufe auf der x-Achse in der Reihenfolge 1 bis 11 erscheinen.

6.9 Layer: Grafiken schrittweise aufbauen

Ein großer Vorteil von ggplot2 ist, dass Grafiken aus mehreren Layern bestehen können.

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  geom_smooth()
`geom_smooth()` using method = 'loess' and formula = 'y ~ x'

Hier werden zwei Darstellungen kombiniert:

  • geom_point() zeigt die einzelnen Beobachtungen.
  • geom_smooth() ergänzt eine geglättete Trendlinie.

Da der Zusammenhang in den DNase-Daten nichtlinear ist, passt eine geglättete Linie oft besser zur Exploration als eine einfache Gerade.

Zum Vergleich kann man trotzdem eine lineare Regressionsgerade einzeichnen:

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  geom_smooth(method = "lm")
`geom_smooth()` using formula = 'y ~ x'

lm steht für linear model, also ein lineares Modell. Dabei wird eine Gerade berechnet, die den Zusammenhang zwischen x und y möglichst gut beschreibt. Man sieht, dass die lineare Gerade den gekrümmten Verlauf nur unzureichend beschreibt.

6.10 Achsen und Transformationen

Die Konzentration in den DNase-Daten nimmt Werte an, die nicht gleichmäßig über die Skala verteilt sind. In solchen Fällen kann eine logarithmische Achse sinnvoll sein.

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  scale_x_log10()

Mit einer logarithmischen x-Achse werden kleine Konzentrationen besser sichtbar. Wichtig ist: Die Daten selbst werden dadurch nicht verändert. Verändert wird die Darstellung der Achse.

Eine häufige Variante kombiniert logarithmische Achse, Punkte und Glättung:

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  geom_smooth(se = FALSE) +
  scale_x_log10()
`geom_smooth()` using method = 'loess' and formula = 'y ~ x'

se = FALSE bedeutet: Das Konfidenzintervall wird nicht angezeigt. Bei geom_smooth() wird normalerweise eine geglättete Linie plus graues Unsicherheitsband dargestellt. Dieses Band ist das Standard-Error-/Konfidenzintervall.

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  geom_smooth(se = TRUE) +
  scale_x_log10()
`geom_smooth()` using method = 'loess' and formula = 'y ~ x'

6.11 Gruppierung mit Farbe

Farbe sollte eine inhaltliche Funktion haben. In den DNase-Daten kann Farbe verwendet werden, um die einzelnen Versuchsläufe zu unterscheiden.

ggplot(DNase, aes(x = conc, y = density, color = Run)) +
  geom_point() +
  scale_x_log10()

Man kann zusätzlich Linien pro Versuchslauf ergänzen:

ggplot(DNase, aes(x = conc, y = density, color = Run, group = Run)) +
  geom_line() +
  geom_point() +
  scale_x_log10()
NoteFarbe bewusst einsetzen

Farben helfen dabei, Muster und Unterschiede sichtbar zu machen. Sie sollten aber gezielt eingesetzt werden.

  • Sparsam verwenden: Zu viele Farben machen Grafiken unübersichtlich.
  • Bedeutung statt Dekoration: Farbe sollte eine Information transportieren.
  • Lesbarkeit beachten: Farben müssen gut unterscheidbar sein.
  • Gruppen: Für Kategorien eignen sich diskrete Farben.
  • Metrische Werte: Für kontinuierliche Werte eignen sich Farbverläufe.
  • Nicht zu viele Gruppenfarben: Bei sehr vielen Kategorien wird Farbe schnell überfordernd.

6.13 Balkendiagramme mit bereits aggregierten Daten

Die Gruppentabelle ist bereits aggregiert: Für jede Gruppe liegt die Anzahl der Zellen n vor.

Daher verwenden wir geom_col():

ggplot(groups, aes(x = sampleGroup, y = n)) +
  geom_col()

Alternativ sieht man in älterem Code häufig:

ggplot(groups, aes(x = sampleGroup, y = n)) +
  geom_bar(stat = "identity")

Beide Varianten zeichnen hier Balken mit der gegebenen Höhe n. Für bereits aggregierte Daten ist geom_col() aber meist verständlicher.

Die x-Achsenbeschriftungen sind lang. Deshalb rotieren wir sie:

ggplot(groups, aes(x = sampleGroup, y = n)) +
  geom_col() +
  theme(axis.text.x = element_text(angle = 90, hjust = 1))

Eine oft noch lesbarere Alternative ist ein horizontales Balkendiagramm:

ggplot(groups, aes(x = n, y = sampleGroup)) +
  geom_col()

6.14 Manuelle Farben

Die Gruppentabelle enthält bereits passende Farben. Diese können wir in ggplot2 verwenden.

Zunächst erstellen wir einen benannten Farbvektor:

groupColor <- setNames(groups$color, groups$sampleGroup)

groupColor

      "#CAB2D6"       "#FDBF6F"       "#A6CEE3"       "#FF7F00"       "#B2DF8A" 
     E4.5 (EPI)  E4.5 (FGF4-KO)       E4.5 (PE) 
      "#1F78B4"       "#E31A1C"       "#33A02C"

Dann verwenden wir ihn mit scale_fill_manual():

ggplot(groups, aes(x = sampleGroup, y = n, fill = sampleGroup)) +
  geom_col() +
  scale_fill_manual(values = groupColor, name = "Gruppe") +
  theme(axis.text.x = element_text(angle = 90, hjust = 1))

Wenn die Farben bereits im Datensatz vorgegeben sind, ist eine manuelle Skala sinnvoll. Ohne scale_fill_manual() würde ggplot2 automatisch eigene Farben wählen.

6.15 Faceting: Teilgrafiken nach Gruppen

Faceting erzeugt mehrere kleine Grafiken nach demselben Prinzip. Das ist besonders hilfreich, wenn man Gruppen vergleichen möchte.

Bei den DNase-Daten können wir für jeden Versuchslauf eine eigene Teilgrafik erzeugen:

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  geom_line() +
  scale_x_log10() +
  facet_wrap(~ Run)

Dadurch erkennt man besser, ob sich einzelne Versuchsläufe auffällig anders verhalten.

Faceting ist oft besser als zu viele Farben in einer einzigen Grafik, weil es Überlagerungen reduziert.

6.16 Beschriftungen und Titel

Eine gute Grafik braucht verständliche Beschriftungen.

ggplot(DNase, aes(x = conc, y = density, color = Run, group = Run)) +
  geom_line() +
  geom_point() +
  scale_x_log10() +
  labs(
    title = "DNase-Assay: Zusammenhang zwischen Konzentration und optischer Dichte",
    subtitle = "Messungen aus mehreren Versuchsläufen",
    x = "Konzentration (log10-Skala)",
    y = "Optische Dichte",
    color = "Versuchslauf"
  )

Beschriftungen sollten nicht einfach Variablennamen wiederholen, sondern für Leserinnen und Leser verständlich sein.

Schlecht:

x = "conc"
y = "density"

Besser:

x = "Konzentration"
y = "Optische Dichte"

6.17 Themes: Gestaltung der Grafik

Themes steuern das Aussehen einer Grafik.

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point() +
  theme_minimal()

Weitere häufige Themes:

theme_bw()
theme_classic()
theme_light()
theme_minimal()

Beispiel mit Anpassungen:

ggplot(DNase, aes(x = conc, y = density, color = Run, group = Run)) +
  geom_line() +
  geom_point() +
  scale_x_log10() +
  labs(
    title = "DNase-Assay",
    x = "Konzentration (log10-Skala)",
    y = "Optische Dichte",
    color = "Versuchslauf"
  ) +
  theme_minimal()

Themes sollten die Lesbarkeit verbessern. Ein Theme ersetzt keine inhaltlich gute Grafik.

6.18 Typische Fehler bei ggplot2

6.18.1 Fehler 1: + vergessen

Falsch:

ggplot(DNase, aes(x = conc, y = density))
  geom_point()

R betrachtet die erste Zeile als abgeschlossen.

Richtig:

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point()

6.18.2 Fehler 2: Variable außerhalb von aes() verwenden

Falsch, wenn die Farbe vom Versuchslauf abhängen soll:

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point(color = Run)

Richtig:

ggplot(DNase, aes(x = conc, y = density, color = Run)) +
  geom_point()

6.18.3 Fehler 3: Konstante Werte innerhalb von aes() setzen

Möglich, aber meistens nicht gemeint:

ggplot(DNase, aes(x = conc, y = density, color = "blue")) +
  geom_point()

Besser:

ggplot(DNase, aes(x = conc, y = density)) +
  geom_point(color = "blue")

6.18.4 Fehler 4: geom_bar() und geom_col() verwechseln

Für Rohdaten, bei denen Häufigkeiten gezählt werden sollen:

ggplot(DNase, aes(x = Run)) +
  geom_bar()

Für bereits aggregierte Daten:

ggplot(groups, aes(x = sampleGroup, y = n)) +
  geom_col()

6.19 Grafiken speichern

Grafiken können mit ggsave() gespeichert werden.

p <- ggplot(DNase, aes(x = conc, y = density, color = Run, group = Run)) +
  geom_line() +
  geom_point() +
  scale_x_log10() +
  labs(
    title = "DNase-Assay",
    x = "Konzentration (log10-Skala)",
    y = "Optische Dichte",
    color = "Versuchslauf"

ggsave("dnase_plot.pdf", plot = p, width = 7, height = 5)
ggsave("dnase_plot.png", plot = p, width = 7, height = 5, dpi = 300)

Für Berichte und wissenschaftliche Arbeiten sind PDF-Dateien oft sinnvoll, weil sie vektorbasiert sind. Für Webseiten oder Präsentationen werden häufig PNG-Dateien verwendet.

6.20 Beispiel: Eine Grafik schrittweise verbessern

In diesem Abschnitt wird gezeigt, wie eine Grafik in ggplot2 Schritt für Schritt verbessert werden kann. Als Beispiel verwenden wir den schon bekannten Datensatz Pima.tr aus dem Paket MASS.

Wir untersuchen die Frage:

Wie unterscheiden sich Glukosewerte und BMI zwischen Personen mit und ohne Diabetes?

Dazu betrachten wir zunächst ein einfaches Streudiagramm und ergänzen anschließend weitere Informationen und Gestaltungselemente.

6.20.1 Schritt 1: Einfaches Streudiagramm

Zunächst erstellen wir ein einfaches Streudiagramm. Auf der x-Achse wird der BMI dargestellt, auf der y-Achse der Glukosewert.

ggplot(Pima.tr, aes(x = bmi, y = glu)) +
  geom_point()

Jeder Punkt steht für eine Person im Datensatz. Die Grafik zeigt, dass es Personen mit sehr unterschiedlichen BMI- und Glukosewerten gibt.

Noch ist aber nicht sichtbar, welche Personen einen positiven oder negativen Diabetesstatus haben.

6.20.2 Schritt 2: Punkte transparenter darstellen

Wenn viele Punkte nah beieinanderliegen, können sie sich überdecken. Mit alpha kann die Transparenz der Punkte angepasst werden.

ggplot(Pima.tr, aes(x = bmi, y = glu)) +
  geom_point(alpha = 0.6)

Durch die Transparenz erkennt man besser, in welchen Bereichen sich mehrere Beobachtungen häufen.

6.20.3 Schritt 3: Diabetesstatus farblich darstellen

Nun wird der Diabetesstatus über die Farbe sichtbar gemacht. Dazu wird type innerhalb von aes() auf die ästhetische Eigenschaft color abgebildet.

ggplot(Pima.tr, aes(x = bmi, y = glu, color = type)) +
  geom_point(alpha = 0.7)

Die Farbe ist hier nicht nur Dekoration, sondern trägt eine inhaltliche Bedeutung. Sie zeigt, ob bei einer Person Diabetes vorliegt oder nicht.

6.20.4 Schritt 4: Punkte größer darstellen

Damit die Punkte besser sichtbar sind, kann ihre Größe angepasst werden.

ggplot(Pima.tr, aes(x = bmi, y = glu, color = type)) +
  geom_point(alpha = 0.7, size = 2)

Das Argument size verändert die Größe der Punkte. Gerade bei Präsentationen kann das die Lesbarkeit verbessern.

6.20.5 Schritt 5: Achsen und Titel beschriften

Eine gute Grafik sollte auch ohne den Quellcode verständlich sein. Deshalb ergänzen wir Achsenbeschriftungen, einen Titel, einen Untertitel und eine Beschriftung für die Legende.

ggplot(Pima.tr, aes(x = bmi, y = glu, color = type)) +
  geom_point(alpha = 0.7, size = 2) +
  labs(
    title = "BMI und Glukosewert im Vergleich",
    subtitle = "Jeder Punkt steht für eine Person im Datensatz",
    x = "Body-Mass-Index (BMI)",
    y = "Glukosewert",
    color = "Diabetesstatus"
  )

Die Grafik ist nun deutlich besser interpretierbar. Titel und Untertitel erklären, worum es geht. Die Achsenbeschriftungen machen klar, welche Variablen dargestellt werden.

6.20.6 Schritt 6: Theme anpassen

Zum Schluss kann das Aussehen der Grafik angepasst werden. Themes verändern nicht die Daten, sondern die Gestaltung der Grafik.

ggplot(Pima.tr, aes(x = bmi, y = glu, color = type)) +
  geom_point(alpha = 0.7, size = 2) +
  labs(
    title = "BMI und Glukosewert im Vergleich",
    subtitle = "Jeder Punkt steht für eine Person im Datensatz",
    x = "Body-Mass-Index (BMI)",
    y = "Glukosewert",
    color = "Diabetesstatus"
  ) +
  theme_minimal()

theme_minimal() erzeugt eine reduzierte Darstellung mit wenig visueller Ablenkung. Die Daten stehen dadurch stärker im Vordergrund.

6.20.7 Schritt 7: Gruppen getrennt betrachten mit Facetten

Eine weitere Möglichkeit besteht darin, die beiden Gruppen in getrennten Teilgrafiken darzustellen. Dafür wird facet_wrap() verwendet.

ggplot(Pima.tr, aes(x = bmi, y = glu)) +
  geom_point(alpha = 0.7, size = 2) +
  facet_wrap(~ type) +
  labs(
    title = "BMI und Glukosewert nach Diabetesstatus",
    subtitle = "Jede Teilgrafik zeigt eine Gruppe",
    x = "Body-Mass-Index (BMI)",
    y = "Glukosewert"
  ) +
  theme_minimal()

Facetten sind besonders hilfreich, wenn Gruppen separat betrachtet werden sollen. Die beiden Teilgrafiken verwenden dieselben Achsen, sodass die Gruppen gut vergleichbar bleiben.

6.20.8 Schritt 8: Farben manuell anpassen

Die Standardfarben von ggplot2 sind für viele Zwecke ausreichend. Manchmal möchte man Farben aber bewusst festlegen, zum Beispiel um Gruppen klarer zu unterscheiden.

ggplot(Pima.tr, aes(x = bmi, y = glu, color = type)) +
  geom_point(alpha = 0.7, size = 2) +
  scale_color_manual(
    values = c("No" = "steelblue", "Yes" = "firebrick"),
    labels = c("No" = "kein Diabetes", "Yes" = "Diabetes")
  ) +
  labs(
    title = "BMI und Glukosewert im Vergleich",
    subtitle = "Farblich unterschieden nach Diabetesstatus",
    x = "Body-Mass-Index (BMI)",
    y = "Glukosewert",
    color = "Diabetesstatus"
  ) +
  theme_minimal()

Mit scale_color_manual() wird festgelegt, welche Farbe für welche Gruppe verwendet wird. Außerdem können die Beschriftungen in der Legende angepasst werden.

6.20.9 Finale Version der Grafik

ggplot(Pima.tr, aes(x = bmi, y = glu, color = type)) +
  geom_point(alpha = 0.75, size = 2) +
  scale_color_manual(
    values = c("No" = "steelblue", "Yes" = "firebrick"),
    labels = c("No" = "kein Diabetes", "Yes" = "Diabetes")
  ) +
  labs(
    title = "BMI und Glukosewert im Vergleich",
    subtitle = "Personen mit Diabetes weisen tendenziell höhere Glukosewerte auf",
    x = "Body-Mass-Index (BMI)",
    y = "Glukosewert",
    color = "Diabetesstatus"
  ) +
  theme_minimal()

Diese finale Version ist deutlich aussagekräftiger als die erste einfache Grafik. Sie zeigt nicht nur den Zusammenhang zwischen BMI und Glukosewert, sondern macht auch den Diabetesstatus sichtbar.

Die Grafik deutet darauf hin, dass Personen mit Diabetes tendenziell höhere Glukosewerte aufweisen. Der BMI allein trennt die Gruppen jedoch nicht eindeutig. Es gibt also keinen einfachen deterministischen Zusammenhang.

Die schrittweise Verbesserung zeigt, dass eine Grafik nicht durch möglichst viele Elemente besser wird, sondern durch gezielte Ergänzungen. Farbe, Beschriftungen, Transparenz und Theme helfen hier, die Daten besser zu verstehen.

NoteMerke: Gute Grafiken sind zielgerichtet

Eine Grafik wird nicht besser, weil sie möglichst viele Gestaltungselemente enthält. Sie wird besser, wenn jedes zusätzliche Element das Verständnis der Daten unterstützt.

Dazu gehören zum Beispiel verständliche Achsenbeschriftungen, ein erklärender Titel, eine klare Legende, passende Farben, Transparenz bei vielen Punkten, Facetten für Gruppenvergleiche und ein zurückhaltendes Theme.

6.20.10 Zusammenfassung GGplot

ggplot2 ist ein mächtiges Werkzeug zur Datenvisualisierung in R. Der zentrale Gedanke ist, dass Grafiken aus wiederverwendbaren Bausteinen bestehen:

ggplot(data = DATEN, aes(x = X, y = Y)) +
  geom_...()

Die wichtigsten Konzepte sind:

  • Daten werden als Data Frame übergeben.
  • aes() beschreibt die Abbildung von Variablen auf visuelle Eigenschaften.
  • geom_*() legt fest, wie die Daten gezeichnet werden.
  • Layer können mit + kombiniert werden.
  • Farben, Facets, Skalen und Themes helfen, komplexere Aussagen sichtbar zu machen.
  • Gute Grafiken entstehen nicht durch möglichst viele Effekte, sondern durch klare Gestaltung und eine eindeutige Aussage.

6.21 Netzwerkvisualisierung

Bisher haben wir vor allem klassische Diagramme betrachtet, zum Beispiel Histogramme, Boxplots oder Streudiagramme. Diese Diagramme eignen sich gut, wenn einzelne Variablen oder Zusammenhänge zwischen zwei metrischen Variablen untersucht werden sollen.

Manche Daten haben jedoch eine andere Struktur: Sie bestehen aus Objekten und Beziehungen zwischen diesen Objekten. Solche Daten können als Netzwerk dargestellt werden.

Typische Beispiele sind:

  • Personen und ihre Freundschaften,
  • Webseiten und ihre Links,
  • Flughäfen und Flugverbindungen,
  • Begriffe und ihre gemeinsamen Vorkommen,
  • Unternehmen und ihre Geschäftsbeziehungen,
  • Gene und ihre Interaktionen.

In einer Netzwerkvisualisierung werden die Objekte als Knoten dargestellt. Die Beziehungen zwischen ihnen werden als Kanten dargestellt.

NoteBegriffe

Ein Knoten steht für ein Objekt, zum Beispiel eine Person, eine Webseite oder einen Ort.

Eine Kante steht für eine Beziehung zwischen zwei Knoten, zum Beispiel eine Freundschaft, eine Verbindung oder eine Interaktion.

6.21.1 Beispiel: Ein kleines soziales Netzwerk

Im folgenden Beispiel betrachten wir ein kleines künstliches Netzwerk. Die Knoten sind Personen. Eine Kante bedeutet, dass zwei Personen miteinander verbunden sind.

library(igraph)
Warning: Paket 'igraph' wurde unter R Version 4.4.3 erstellt

    decompose, spectrum

verbindungen <- data.frame(
  von = c("Anna", "Anna", "Ben", "Ben", "Clara", "David", "Eva", "Eva", "Fatima"),
  zu  = c("Ben", "Clara", "Clara", "David", "Eva", "Eva", "Fatima", "Gustav", "Gustav")
)

4    Ben  David
5  Clara    Eva
6  David    Eva
7    Eva Fatima
8    Eva Gustav

Der Datensatz besteht aus zwei Spalten:

  • von: Startknoten der Beziehung,
  • zu: Zielknoten der Beziehung.

Jede Zeile beschreibt also eine Verbindung zwischen zwei Personen.

6.21.2 Netzwerkobjekt erstellen

Damit R die Daten als Netzwerk interpretieren kann, erstellen wir zunächst ein Netzwerkobjekt.

netzwerk <- graph_from_data_frame(verbindungen, directed = FALSE)

netzwerk
IGRAPH fc22725 UN-- 7 9 -- 
+ attr: name (v/c)
+ edges from fc22725 (vertex names):
[1] Anna  --Ben    Anna  --Clara  Ben   --Clara  Ben   --David  Clara --Eva   
[6] David --Eva    Eva   --Fatima Eva   --Gustav Fatima--Gustav

Das Argument directed = FALSE bedeutet, dass die Beziehungen ungerichtet sind. Eine Verbindung zwischen Anna und Ben wird also einfach als gegenseitige Verbindung betrachtet.

Bei gerichteten Netzwerken wäre die Richtung wichtig. Das wäre zum Beispiel bei Twitter/X-Followern oder Webseitenlinks der Fall.

6.21.3 Einfache Netzwerkvisualisierung

Mit plot() kann das Netzwerk direkt visualisiert werden.

plot(netzwerk)

Die Darstellung zeigt die Personen als Knoten und die Verbindungen als Linien zwischen den Knoten.

Allerdings ist diese erste Version noch sehr schlicht. Wie bei anderen Diagrammen können wir die Grafik Schritt für Schritt verbessern.

6.21.4 Knoten und Beschriftungen anpassen

Zunächst können wir die Größe der Knoten, die Farbe und die Beschriftungen anpassen.

plot(
  netzwerk,
  vertex.size = 30,
  vertex.color = "lightblue",
  vertex.label.color = "black",
  vertex.label.cex = 0.9,
  edge.color = "gray60",
  main = "Ein kleines soziales Netzwerk"
)

Die wichtigsten Argumente sind:

  • vertex.size: Größe der Knoten,
  • vertex.color: Farbe der Knoten,
  • vertex.label.color: Farbe der Beschriftung,
  • vertex.label.cex: Größe der Beschriftung,
  • edge.color: Farbe der Kanten.

6.21.5 Zentrale Knoten hervorheben

In Netzwerken ist häufig interessant, welche Knoten besonders gut verbunden sind. Eine einfache Kennzahl dafür ist der Grad eines Knotens.

Der Grad gibt an, mit wie vielen anderen Knoten ein Knoten verbunden ist.

grad <- degree(netzwerk)

grad
  Anna    Ben  Clara  David    Eva Fatima Gustav 
     2      3      3      2      4      2      2

Nun können wir die Knotengröße vom Grad abhängig machen. Personen mit vielen Verbindungen erscheinen dadurch größer.

plot(
  netzwerk,
  vertex.size = grad * 8,
  vertex.color = "lightblue",
  vertex.label.color = "black",
  vertex.label.cex = 0.9,
  edge.color = "gray60",
  main = "Knotengröße nach Anzahl der Verbindungen"
)

In dieser Grafik werden stärker vernetzte Personen visuell hervorgehoben. Das kann helfen, zentrale Akteure in einem Netzwerk schneller zu erkennen.

TipMerke

Bei Netzwerkvisualisierungen sollte die Gestaltung eine inhaltliche Bedeutung haben.

Wenn Knoten unterschiedlich groß dargestellt werden, sollte diese Größe etwas ausdrücken, zum Beispiel die Anzahl der Verbindungen oder eine andere Kennzahl.

6.21.6 Layouts verändern

Bei Netzwerkvisualisierungen gibt es meist keine feste x- oder y-Achse. Die Position der Knoten wird durch ein sogenanntes Layout bestimmt.

Ein Layout legt fest, wie die Knoten im Raum angeordnet werden.

plot(
  netzwerk,
  layout = layout_with_fr(netzwerk),
  vertex.size = grad * 8,
  vertex.color = "lightblue",
  vertex.label.color = "black",
  vertex.label.cex = 0.9,
  edge.color = "gray60",
  main = "Netzwerk mit Force-Directed Layout"
)

Das Layout layout_with_fr() ist ein sogenanntes force-directed Layout. Dabei werden verbundene Knoten eher näher beieinander platziert, während nicht direkt verbundene Knoten stärker auseinanderliegen.

Dadurch entstehen häufig gut lesbare Netzwerkstrukturen.

6.21.7 Netzwerk mit ggraph

Für modernere Netzwerkvisualisierungen kann das Paket ggraph verwendet werden. Es orientiert sich an der Logik von ggplot2, ist aber speziell für Graphen und Netzwerke gedacht.

library(ggraph)
Warning: Paket 'ggraph' wurde unter R Version 4.4.3 erstellt
ggraph(netzwerk, layout = "fr") +
  geom_edge_link(color = "gray70") +
  geom_node_point(size = 6, color = "lightblue") +
  geom_node_text(aes(label = name), repel = TRUE) +
  labs(
    title = "Ein kleines soziales Netzwerk",
    subtitle = "Knoten stehen für Personen, Kanten für Verbindungen"
  ) +
  theme_void()

Hier werden drei zentrale Bausteine verwendet:

  • geom_edge_link() zeichnet die Kanten,
  • geom_node_point() zeichnet die Knoten,
  • geom_node_text() ergänzt die Knotennamen.

Das Theme theme_void() entfernt Achsen, Gitterlinien und Hintergrundelemente. Das ist bei Netzwerkvisualisierungen oft sinnvoll, weil die Achsen keine inhaltliche Bedeutung haben.

6.21.8 Knoten nach Grad einfärben

Auch mit ggraph können Netzwerke schrittweise informativer gestaltet werden. Im folgenden Beispiel wird der Grad eines Knotens berechnet und anschließend für die Farbe der Knoten verwendet.

V(netzwerk)$grad <- degree(netzwerk)

ggraph(netzwerk, layout = "fr") +
  geom_edge_link(color = "gray75") +
  geom_node_point(aes(size = grad, color = grad)) +
  geom_node_text(aes(label = name), repel = TRUE) +
  scale_size_continuous(range = c(4, 10)) +
  labs(
    title = "Zentrale Knoten im Netzwerk",
    subtitle = "Größere und dunklere Knoten haben mehr Verbindungen",
    size = "Anzahl Verbindungen",
    color = "Anzahl Verbindungen"
  ) +
  theme_void()

Diese Darstellung zeigt nicht nur, wer mit wem verbunden ist. Sie macht zusätzlich sichtbar, welche Personen besonders viele Verbindungen haben.

6.21.9 Gerichtete Netzwerke

Nicht alle Netzwerke sind ungerichtet. Manchmal hat eine Beziehung eine Richtung.

Beispiele:

  • Eine Webseite verlinkt auf eine andere Webseite.
  • Eine Person folgt einer anderen Person.
  • Ein Paket wird von einem Ort zu einem anderen transportiert.
  • Eine E-Mail wird von einer Person an eine andere gesendet.

In solchen Fällen kann ein gerichtetes Netzwerk verwendet werden.

links <- data.frame(
  von = c("Startseite", "Startseite", "Kurs", "Kurs", "Material", "Übung"),
  zu  = c("Kurs", "Material", "Übung", "Prüfung", "Übung", "Prüfung")
)

webnetz <- graph_from_data_frame(links, directed = TRUE)

plot(
  webnetz,
  vertex.size = 35,
  vertex.color = "lightyellow",
  vertex.label.color = "black",
  edge.arrow.size = 0.5,
  edge.color = "gray50",
  main = "Beispiel für ein gerichtetes Netzwerk"
)

Die Pfeile zeigen die Richtung der Beziehung. Dadurch erkennt man, von welchem Knoten eine Verbindung ausgeht und wohin sie führt.

6.21.10 Wann sind Netzwerkvisualisierungen sinnvoll?

Netzwerkvisualisierungen eignen sich besonders dann, wenn die Beziehungen zwischen Objekten im Mittelpunkt stehen.

Sie sind weniger geeignet, wenn nur einzelne Variablen verglichen werden sollen. Für Verteilungen, Mittelwerte oder Zusammenhänge zwischen zwei metrischen Variablen sind Histogramme, Boxplots oder Streudiagramme meist besser geeignet.

NoteNetzwerkvisualisierung

Eine Netzwerkvisualisierung beantwortet vor allem Fragen wie:

  • Welche Objekte sind miteinander verbunden?
  • Welche Knoten sind besonders zentral?
  • Gibt es Gruppen oder Cluster?
  • Gibt es isolierte oder schwach verbundene Knoten?
  • Gibt es gerichtete Beziehungen?

6.21.11 Grenzen von Netzwerkvisualisierungen

Netzwerkdiagramme können schnell unübersichtlich werden. Schon bei einigen hundert Knoten und Kanten kann eine Darstellung schwer lesbar sein.

Typische Probleme sind:

  • zu viele Knoten,
  • zu viele Kanten,
  • überlappende Beschriftungen,
  • unklare Farben,
  • zu viele visuelle Kodierungen gleichzeitig.

Deshalb sollten Netzwerkvisualisierungen besonders sorgfältig gestaltet werden.

TipMerke

Netzwerkvisualisierungen sind besonders nützlich, wenn Beziehungen zwischen Objekten untersucht werden sollen.

Sie zeigen nicht nur einzelne Werte, sondern Strukturen: Verbindungen, zentrale Knoten, Gruppen und mögliche Muster im Netzwerk.
