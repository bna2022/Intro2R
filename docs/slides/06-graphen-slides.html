Lernziele

Nach dieser Einheit können Sie:

  • erklären, was Knoten und Kanten sind,
  • Netzwerke als Kantenliste, Knotenliste und Adjazenzmatrix darstellen,
  • aus Tabellen ein igraph-Objekt erzeugen,
  • mit Adjazenzmatrizen einfache Erreichbarkeitsfragen beantworten,
  • Netzwerke mit plot() visualisieren und gestalten.

Einführung

Setup

Für die Beispiele verwenden wir vor allem igraph.

library(igraph)

Note

igraph verbindet drei Dinge: Netzwerkdaten speichern, Netzwerke analysieren und Netzwerke visualisieren.

Was ist ein Netzwerk?

Manche Daten bestehen nicht nur aus einzelnen Beobachtungen, sondern aus Objekten und Beziehungen.

Beispiele:

  • Personen und Freundschaften
  • Figuren und Beziehungen
  • Webseiten und Links
  • Gene und Interaktionen
  • Patient:innen und Kontakte

Was ist ein Netzwerk?

Tip

Ein Knoten steht für ein Objekt.
Eine Kante steht für eine Beziehung zwischen zwei Objekten.

Netzwerk-Repräsentationen

Netzwerk-Repräsentationen

Ein Netzwerk kann unterschiedlich gespeichert werden:

Repräsentation Idee
Kantenliste Jede Zeile ist eine Beziehung
Knotenliste Zusatzinformationen zu den Knoten
Adjazenzmatrix Zeilen und Spalten sind Knoten
igraph-Objekt Netzwerkstruktur für Analyse und Plot

Kantenliste

Eine Kantenliste beschreibt, welche Knoten miteinander verbunden sind.

verbindungen <- data.frame(
  von = c("Anna", "Anna", "Ben", "Ben", "Clara", "David"),
  zu  = c("Ben", "Clara", "Clara", "David", "Eva", "Eva")
)

verbindungen
    von    zu
1  Anna   Ben
2  Anna Clara
3   Ben Clara
4   Ben David
5 Clara   Eva
6 David   Eva

Aus Kantenliste wird Graph

g_klein <- graph_from_data_frame(
  d = verbindungen,
  directed = FALSE
)

g_klein
IGRAPH 9ea72e5 UN-- 5 6 -- 
+ attr: name (v/c)
+ edges from 9ea72e5 (vertex names):
[1] Anna --Ben   Anna --Clara Ben  --Clara Ben  --David Clara--Eva  
[6] David--Eva

Tip

Eine Kantenliste ist oft die einfachste Form, ein Netzwerk tabellarisch zu speichern.

Gerichtete und ungerichtete Graphen

Bei einem ungerichteten Graphen zählt nur, dass eine Verbindung existiert.

g_ungerichtet <- graph_from_data_frame(
  verbindungen,
  directed = FALSE
)

Bei einem gerichteten Graphen hat jede Kante eine Richtung.

g_gerichtet <- graph_from_data_frame(
  verbindungen,
  directed = TRUE
)

Visualisierung: ungerichtet

plot(g_ungerichtet)

Visualisierung: gerichtet

plot(g_gerichtet)

personen <- data.frame(

  gruppe = c("A", "A", "A", "B", "B"),
  alter  = c(22, 24, 21, 25, 23)

personen

Kantenliste + Knotenliste

Die erste Spalte der Knotenliste muss zu den Knotennamen in der Kantenliste passen.

g_attr <- graph_from_data_frame(
  d = verbindungen,
  vertices = personen,
  directed = FALSE
)

V(g_attr)$gruppe
[1] "A" "A" "A" "B" "B"
V(g_attr)$alter
[1] 22 24 21 25 23

Important

Die Knotenliste ergänzt Attribute. Die Kantenliste definiert die Beziehungen.

Adjazenzmatrix

Eine Adjazenzmatrix ist eine Matrixdarstellung eines Netzwerks.

  • Zeilen: Startknoten
  • Spalten: Zielknoten
  • 1: Kante vorhanden
  • 0: keine Kante vorhanden
A <- as_adjacency_matrix(g_klein, sparse = FALSE)
A
      Anna Ben Clara David Eva
Anna     0   1     1     0   0
Ben      1   0     1     1   0
Clara    1   1     0     0   1
David    0   1     0     0   1
Eva      0   0     1     1   0

Aus Matrix wird Graph

g_aus_matrix <- graph_from_adjacency_matrix(
  A,
  mode = "undirected",
  diag = FALSE
)

plot(g_aus_matrix)

Rechnen mit Adjazenzmatrizen

Die Matrix A zeigt direkte Verbindungen.

Die Matrix A %*% A zählt Wege der Länge 2.

A2 <- A %*% A
A2
      Anna Ben Clara David Eva
Anna     2   1     1     1   1
Ben      1   3     1     0   2
Clara    1   1     3     2   0
David    1   0     2     2   0
Eva      1   2     0     0   2

Note

Wenn in A2[i, j] ein Wert größer als 0 steht, gibt es mindestens einen Weg von Knoten i nach Knoten j über genau einen Zwischenknoten.

Erreichbarkeit

Für kleine Graphen kann man Erreichbarkeit über Matrixpotenzen prüfen.

# Gewichtete Adjazenzmatrix in eine 0/1-Matrix umwandeln
A_bin <- ifelse(A > 0, 1, 0)

# Wege mit Länge 1, 2 und 3 berechnen
wege_1 <- A_bin
wege_2 <- A_bin %*% A_bin
wege_3 <- A_bin %*% A_bin %*% A_bin

# Prüfen, ob mindestens ein Weg existiert
R <- (wege_1 + wege_2 + wege_3) > 0

# TRUE/FALSE in 1/0 umwandeln
ifelse(R, 1, 0)
      Anna Ben Clara David Eva
Anna     1   1     1     1   1
Ben      1   1     1     1   1
Clara    1   1     1     1   1
David    1   1     1     1   1
Eva      1   1     1     1   1

Erreichbarkeit

Tip

Die Erreichbarkeitsmatrix zeigt, ob Knoten über Wege bis zu einer bestimmten Länge verbunden sind.

Netzwerkdaten einlesen

Harry-Potter-Daten einlesen

In echten Projekten liegen Netzwerkdaten häufig in Dateien.

characters <- read.csv("characters.csv", header = TRUE, as.is = TRUE)
relations  <- read.csv("relations.csv",  header = TRUE, as.is = TRUE)

Die Daten bestehen aus:

  • characters.csv: Knoten, also Figuren
  • relations.csv: Kanten, also Beziehungen

Note

Im Harry-Potter-Beispiel steht + für positive und - für negative Beziehungen.

Daten prüfen

Vor dem Erzeugen des Graphen sollten die Daten geprüft werden.

nrow(characters)
length(unique(characters$id))

nrow(relations)
nrow(unique(relations[, c("source", "target")]))

knoten_ids <- as.character(characters$id)
kanten_ids <- as.character(unique(c(relations$source, relations$target)))
setdiff(kanten_ids, knoten_ids)

Tip

Wenn setdiff() leer ist, verweisen alle Kanten auf vorhandene Knoten.

Doppelte Kanten verdichten

Zwischen denselben Figuren können mehrere Beziehungen vorkommen.

relations_gewichtet <- aggregate(
  x = list(weight = rep(1, nrow(relations))),
  by = list(
    source = relations$source,
    target = relations$target,
    type   = relations$type
  ),
  FUN = sum
)

relations_gewichtet$source <- as.character(relations_gewichtet$source)
relations_gewichtet$target <- as.character(relations_gewichtet$target)

head(relations_gewichtet)

Note

Die Spalte weight zählt, wie häufig eine bestimmte Beziehung vorkommt.

Knotendaten für igraph vorbereiten

igraph verwendet das Attribut name als Knoten-ID.

characters_igraph <- data.frame(
  name      = as.character(characters$id),
  character = characters$name,
  bio       = characters$bio,
  house     = trimws(characters$house),
  alive     = trimws(characters$alive)
)

head(characters_igraph)

Harry-Potter-Netzwerk erzeugen

g_hp <- graph_from_data_frame(
  d = relations_gewichtet,
  vertices = characters_igraph,
  directed = TRUE
)

g_hp

Harry-Potter-Netzwerk erzeugen

Das Netzwerk enthält:

  • Figuren als Knoten
  • Beziehungen als gerichtete Kanten

Attribute auslesen

Netzwerk-Visualisierung

Netzwerk-Visualisierung

Die einfachste Visualisierung entsteht mit plot().

plot(g_hp)

Important

Die erste Netzwerkvisualisierung ist oft unübersichtlich. Das ist normal. Gute Netzwerkvisualisierung entsteht schrittweise.

Labels reduzieren

Bei größeren Netzwerken überlappen Labels schnell.

plot(
  g_hp,
  vertex.label = NA,
  vertex.size = 6,
  edge.arrow.size = 0.3
)

Tip

Nicht jeder Knoten muss beschriftet werden.

Layouts

Ein Layout bestimmt, wo Knoten im Plot platziert werden.

set.seed(123)
layout_hp <- layout_with_fr(g_hp)

plot(
  g_hp,
  layout = layout_hp,
  vertex.label = NA,
  vertex.size = 6,
  edge.arrow.size = 0.3
)

Layouts

Note

Viele Layouts enthalten Zufall. Für reproduzierbare Grafiken: set.seed() setzen oder das Layout speichern. Eine Übersicht über Layout-Funktionen findet sich in der igraph-Dokumentation zu Layouts.

Knoten nach Attribut einfärben

house_farbe <- c(
  "Gryffindor" = "firebrick",
  "Slytherin" = "darkgreen",
  "Ravenclaw" = "steelblue",
  "Hufflepuff" = "goldenrod",
  "no information" = "grey80"
)

V(g_hp)$color <- unname(house_farbe[V(g_hp)$house])
V(g_hp)$color[is.na(V(g_hp)$color)] <- "grey80"

Plot mit Farben und Legende

plot(
  g_hp,
  layout = layout_hp,
  vertex.label = NA,
  vertex.size = 7,
  edge.arrow.size = 0.3
)

legend(
  "topleft",
  legend = names(house_farbe),
  col = house_farbe,
  pch = 19,
  bty = "n"
)

Knotengröße nach Grad

Der Grad beschreibt, mit wie vielen Kanten ein Knoten verbunden ist.

grad_gesamt <- degree(g_hp, mode = "all")
V(g_hp)$size <- 4 + grad_gesamt * 0.6

plot(
  g_hp,
  layout = layout_hp,
  vertex.label = NA,
  vertex.size = V(g_hp)$size,
  edge.arrow.size = 0.3
)

Kanten nach Beziehungstyp gestalten

E(g_hp)$color <- ifelse(E(g_hp)$type == "+", "darkblue", "firebrick")
E(g_hp)$lty   <- ifelse(E(g_hp)$type == "+", 1, 2)
E(g_hp)$width <- 1 + E(g_hp)$weight

plot(
  g_hp,
  layout = layout_hp,
  vertex.label = NA,
  vertex.size = V(g_hp)$size,
  edge.arrow.size = 0.3,
  edge.curved = 0.2
)

Teilnetzwerk visualisieren

Bei größeren Netzwerken ist ein Ausschnitt oft lesbarer.

g_gryffindor <- induced_subgraph(
  g_hp,
  vids = V(g_hp)[house == "Gryffindor"]
)

plot(
  g_gryffindor,
  layout = layout_with_fr(g_gryffindor),
  vertex.label = V(g_gryffindor)$character,
  vertex.label.cex = 0.7,
  vertex.size = 6 + degree(g_gryffindor, mode = "all"),
  edge.arrow.size = 0.4,
  edge.curved = 0.2,
  main = "Teilnetzwerk: Gryffindor"
)

Zusammenfassung

  • Netzwerke bestehen aus Knoten und Kanten.
  • Kantenlisten sind praktisch zum Speichern und Einlesen.
  • Knotenlisten ergänzen Attribute.
  • Adjazenzmatrizen sind nützlich für rechnerische Fragen.
  • Matrixprodukte zeigen Wege über mehrere Schritte.
  • Gute Netzwerkplots entstehen iterativ: Layout, Labels, Farben, Größen und Kanten gestalten.
